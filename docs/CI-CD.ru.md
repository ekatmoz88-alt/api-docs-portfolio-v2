# Архитектура CI/CD и подтверждение выполнения

## Назначение

Документ описывает CI/CD workflow, настроенный в этом репозитории. Здесь отдельно указаны реализованная автоматизация, фактически выполненные проверки и проверки, которых пока нет в пайплайне.

## Архитектура

Workflow определён в файле [`.github/workflows/ci.yml`](../.github/workflows/ci.yml).

```text
Push в main / Pull request в main
                 |
                 v
       Контроль качества API-контрактов
       - checkout исходного кода
       - настройка Node.js 24.22.2
       - фиксация версии npm 11.19.1
       - установка зависимостей (npm ci)
       - аудит npm-пакетов (high severity)
       - проверка двух OpenAPI-файлов через Spectral
       - проверка двух OpenAPI-файлов через Redocly
                 |
                 v
             Сборка Jekyll
       - настройка GitHub Pages
       - сборка сайта документации
       - загрузка Pages artifact при push в main
                 |
                 v
          Публикация GitHub Pages
       - публикация загруженного артефакта
       - получение URL опубликованного сайта
```

Workflow запускается при:
- push в ветку `main`;
- создании pull request с целевой веткой `main`.

Публикация выполняется только при push в `main`. Сборка зависит от успешного завершения проверок качества, а публикация — от успешной сборки.

## Настроенные проверки качества

| Проверка | Конфигурация / команда | Область проверки |
|---|---|---|
| Установка зависимостей | `npm ci --no-audit --no-fund` | Зафиксированные npm-зависимости |
| Аудит зависимостей | `npm audit --audit-level=high` | Уязвимости высокого уровня |
| Spectral | `npm run lint:spectral` | `openapi/openapi.yaml`, `openapi/navigation-api.yaml` |
| Redocly | `npm run lint:redocly` | Обе OpenAPI-спецификации |
| Сборка документации | `actions/jekyll-build-pages` | Сайт Jekyll |
| Публикация Pages | `actions/upload-pages-artifact`, `actions/deploy-pages` | Push в `main` |

В текущем `package.json` определены команды валидации Spectral и Redocly. Отдельный набор автоматизированных модульных, интеграционных или сквозных тестов (unit / integration / E2E) не настроен. Поэтому успешное выполнение workflow подтверждает прохождение настроенных проверок качества, сборки и публикации, но не доказывает корректность runtime-поведения Orders API.
