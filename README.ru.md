# Orders API Documentation (Портфолио-проект)

Интерактивная документация к API, созданная с использованием **OpenAPI 3.1**, **Redoc** и **GitHub Actions**.

[Открыть документацию на GitHub Pages](https://ekatmoz88-alt.github.io/api-docs-portfolio-v2/)

## 📌 О проекте и контекст
Данный репозиторий представляет собой **публичное демо**, основанное на профессиональном опыте работы техническим писателем в **Pelita (2021–2024)** и последующем фрилансе.

Реальные рабочие материалы (внутренние спецификации API, документация по интеграциям и ПО) являются конфиденциальными (NDA). В этом проекте те же самые задачи, структура и подходы к документированию продемонстрированы на примере вымышленного API заказов ("Orders API").

Цель демо: показать навыки работы со спецификациями OpenAPI 3.1, проектирования обработки ошибок и настройки CI/CD для документации.

*Примечание: Аккаунт GitHub создан недавно. Предыдущая техническая документация (2012–2024 гг.), включая документацию по API и интеграциям для Pelita, создавалась во внутренних корпоративных системах и закрыта для публичного доступа.*

## 🛠 Технологический стек
- **OpenAPI 3.1** (YAML-спецификация)
- **Redoc** (рендеринг интерфейса документации)
- **GitHub Actions** (CI/CD: авто-линтер + автодеплой)
- **GitHub Pages** (хостинг)

## ✨ Ключевые особенности
- **Интерактивные примеры кода**: Реализовано расширение `x-codeSamples` для cURL, Python и JavaScript.
- **Схемы обработки ошибок**: Стандартизированные ответы `ProblemDetails` (RFC 7807) для ошибок 400/401 с реальными JSON-примерами.
- **Автоматический контроль качества**: CI-пайплайн запускает линтер OpenAPI при каждом коммите в ветку `main`.
- **Автодеплой**: При мердже в `main` документация автоматически собирается и публикуется на Pages.

## 💼 Фокус на DX (Developer Experience)
Документация создана не только для чтения, но и для удобства разработчиков: понятные примеры запросов/ответов, готовые к копированию (copy-paste) сниппеты кода, строгая валидация схем и прозрачное описание ошибок.
